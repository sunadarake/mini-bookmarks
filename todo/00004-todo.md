# オプション画面と JSON エクスポート/インポート

## 概要
オプション画面を新設し、保存記事の JSON エクスポートと、ファイル選択・ドラッグ&ドロップによるインポートを実装する。インポートは内容を確認するプレビュー（「N件を保存します」）を出し、保存ボタンで確定する。記事の順番は維持する。

## 調査結果
- `manifest.json` に `options_ui` は無い。`permissions` は `storage` / `unlimitedStorage` / `tabs`
- データは `chrome.storage.local` の `MiniBookMark_Items` に `{ url, hostName, title, read }` の配列で保存（`src/lib.js`）
- `src/lib.js` に純粋関数と保存処理が集約されている。テストは `tests/lib.test.js`
- `src/common.css` に `.section`、`.section input[type="file"]`、`.alert`、`.btn-primary` が既にある
- `build.sh` は `src/` を丸ごと zip に入れるため、ファイル追加だけで配布物に含まれる

## 実装計画

## 決定事項
- インポートは既存に追加し、インポート項目を先頭に置く
- 同一 URL はインポート側を優先する
- JSON は `{ version, exportedAt, items }` のメタ情報付きオブジェクト
- favorite は復元し、read は復元しない
- 順序はインポートした配列の順を維持する
- `version` は固定値 `1` にする（`manifest.json` は参照しない）
- インポートのプレビューは合計件数のみ、favorite は存在すればそのまま通す
- 手動確認（Chrome 上での操作）はこの環境では未実施

## 懸念点・未決事項
- `version` の値は拡張機能のバージョンに合わせるか固定値にするか。実装時に `manifest.json` を参照せず固定文字列にする想定
- インポートのプレビューで favorite 件数などを出すかは最小限（合計件数のみ）とする
- この TODO の時点では favorite 機能本体は未実装のため、favorite は「存在すれば通す」扱いにする
