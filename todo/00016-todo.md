# RELEASE.md を publish.sh に統合して削除

## 概要
リポジトリに置かれている `RELEASE.md` は `publish.sh` が実行時に生成する一時ファイルと内容が重複し、バージョンも古いまま残っている。リリースノート本文は `publish.sh` に組み込み、バージョンは `manifest.json` から取得した値で動的に埋め込む。`RELEASE.md` は追跡対象から削除し、実行時にファイルを作らないようにする。

## 調査結果
- `publish.sh:34-41` で `cat > RELEASE.md` のヒアドキュメントによりリリースノートを生成し、`publish.sh:49` の `gh release create --notes-file RELEASE.md` で利用している
- 追跡されている `RELEASE.md` は v3.3.2 の内容で、`manifest.json` の 3.5.0 と不整合
- `AGENTS.md:18` に「`RELEASE.md` を生成し」という記述がある
- その他に `RELEASE.md` を参照する箇所はない

## 実装計画
- [x] ステップ1: `publish.sh` のリリースノートをヒアドキュメントの変数に置き換え、`--notes-file` ではなく `--notes` で渡す（`publish.sh`）
- [x] ステップ2: `publish.sh` 冒頭コメントを実態に合わせて更新する（`publish.sh`）
- [x] ステップ3: `RELEASE.md` を `git rm` で削除する
- [x] ステップ4: `AGENTS.md` のリリース手順の記述を「ノートを組み込んで生成」に更新する（`AGENTS.md`）

## テスト・確認方法
- [x] `bash -n publish.sh` で構文エラーがない
- [x] `publish.sh` 内でバージョンが `manifest.json` から動的に埋め込まれている
- [x] `RELEASE.md` がリポジトリに存在しない
- [x] `npm test` / `npm run lint` が通る

## 決定事項
- リリースノートは実行時にファイルへ書き出さず、`gh release create` の `--notes` に直接渡す
- バージョンは既存どおり `manifest.json` から取得する

## 懸念点・未決事項
- `publish.sh` の実際のリリース作成は `gh` と remote が必要なため、ローカルでは実行しない
